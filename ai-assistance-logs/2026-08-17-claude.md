## 1. User request

Build QDVC Stickies, a single-page web application where the screen is a place to put sticky notes. Kind of like a Kanban board, but not strictly following typical 'kanban' type methodologies. The user starts with 2 vertical panels. The first one is "Now" and the second one is "Later". The former takes up about a third of the horizontal space, and the latter takes up the remaining two-thirds.

The user can add sticky notes and move them around the screen. By default the user can place them anywhere within the 2 panels (not between them).

Everything is stored in browser LocalStorage.

Put a menubar at the top of the screen. Edit --> Preferences opens up a Preferences modal which uses a master-detail layout. Two to start off:

1. The user can change the font of the sticky notes;
2. The user can clear all LocalStorage (which also loses all the sticky notes).

File --> Import and File --> Export allow the user to preserve the data between settings resets (or to switch to a different web browser). I trust you to handle the choice of data format and its structure.

Set up the project like so:

`docs/`
- `index.html`
- `css/`
- `js/`

This allows CSS and JS files to be well-modularised but still loaded directly from the filesystem. Do not allow any external dependencies on CDNs, Google Fonts, or the like.

## 2. LLM response

Built and packaged. Open `docs/index.html` directly — no server, no build step, no external requests.

The look is a self-healing cutting mat on a workbench: a dark teal gridded surface where the paper is the only saturated thing, with the chrome as machined plates. The strip between the panels is drawn as a ruler channel, because that's the one place a note can't go — the constraint you specified is the signature element rather than an invisible rule.

Your spec was clear enough to build without blocking, so here are the calls I made where it left room:

- **Placement** is free-form absolute positioning within a panel, not a flow list. Drag a note across the channel to move it between panels; release over the channel and it lands in the nearer panel. `Esc` mid-drag puts it back.
- **Notes** also get resize (bottom-right corner), six paper colours, click-to-raise stacking, and a small persistent tilt derived from their id.
- **Scripts are classic `<script>` tags**, not ES modules — modules are blocked by CORS over `file://`, which would have broken the "load from the filesystem" requirement.
- **Typefaces** are seven OS-installed stacks (Humanist, Marker, Grotesque, Old style, Typewriter, Mono, System), since no font can be fetched. Preferences → Notes also has a text size slider and a live preview on real paper.
- **Preferences → Storage** shows note count, bytes stored and last-saved time, offers Export, and clears storage behind a confirmation. It calls `localStorage.clear()` — the whole origin, as you asked, not just the app's key.
- **Format** is one JSON document (`schema: 1`) holding preferences, panels and notes; panel widths are flex shares, so the ⅓/⅔ split lives in data. Import shows what's in the file, then offers Replace board or Merge into board. Malformed values are repaired or dropped rather than crashing.
- Keyboard: `Ctrl/⌘ Shift N`, `Ctrl/⌘ O`, `Ctrl/⌘ E`, `Ctrl/⌘ ,`; menus are arrow-key navigable.

I ran two jsdom suites against the real files (71 assertions: mount, render, tallies, colour changes, preference plumbing, persistence, clear, import replace/merge, malformed input, then drag across panels, channel release, `Esc` cancel, clamping, resize floors, typing, z-order). Both clean. Layout and typography can't be verified headlessly, so those are worth your eye — particularly the note grip's hover reveal and the mobile stacked layout below 720px.
